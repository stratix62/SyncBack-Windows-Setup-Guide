Think of it as a quiet harbor master for your files: it does not shout, it does not demand attention, it simply ensures every vessel — every document, photo, project folder, or database archive — reaches its intended dock safely.

This repository hosts the complete distribution bundle, configuration templates, profile examples, and documentation for the 2026 edition. The project is written with an emphasis on **reliable disaster recovery**, **two-way mirroring**, **incremental snapshots**, and **scheduled automation** that behaves predictably even on machines with modest hardware.

The 2026 release is the most refined iteration to date. It introduces a redesigned task engine, a lighter memory footprint, and a friendlier onboarding experience aimed at both home users and small business operators who need dependable duplication of critical data without wrestling with enterprise complexity.

## 🧭 Why SyncBack-2026 Exists

Most backup utilities fall into one of two camps: either they are featherweight scripts that require a command-line degree to operate, or they are sprawling suites that consume more resources than the files they protect. SyncBack-2026 was conceived to occupy the middle ground — a tool that feels light in the hand but carries serious engineering underneath.

The guiding metaphor is a **lighthouse keeper**. The keeper does not chase every ship; the keeper maintains a steady beam so ships can find their way. In the same manner, SyncBack-2026 maintains a steady, verifiable replica of your important data so that when something goes wrong — a drive fails, a folder is accidentally emptied, a ransomware event encrypts your working set — you have a trustworthy fallback already waiting.

Key motivations behind the 2026 line:

- Predictable behavior across Windows 11 and Windows 10.
- Human-readable logs instead of cryptic error codes.
- Profiles that can be exported, imported, and shared between machines.
- A scheduler that respects system idle time and battery state.
- Transparent conflict resolution when two versions of a file disagree.

## ✨ Feature Constellation

Below is a non-exhaustive constellation of capabilities. Each "star" is a feature cluster rather than a single toggle.

- **Bidirectional Mirroring** — Keep two folders in perfect agreement. When a file changes on either side, the change propagates in the direction you define, with conflict previews before any write occurs.
- **Incremental Snapshotting** — Only the deltas travel. After the initial pass, subsequent runs move just the changed blocks, dramatically reducing time and wear on storage media.
- **Versioned Restore Points** — Retain multiple historical versions of a file so you can rewind to a Tuesday morning state without restoring an entire volume.
- **Scheduled Automation** — Define triggers by time, by system event (logon, idle, USB insertion), or by manual invocation.
- **Dry-Run Simulation** — Preview exactly what a profile intends to do before it touches a single byte.
- **Filtering Rules** — Include or exclude by wildcard, extension, size, age, or attribute.
- **Compression & Deduplication** — Optional packing of backup sets, with duplicate block elimination to conserve destination space.
- **Integrity Verification** — Cryptographic checksums confirm that what was written matches what was read.
- **Portable Profiles** — Carry your configuration on a removable drive and launch the same behavior on any Windows machine.
- **Notification Hooks** — Send completion summaries to a tray notification, a log file, or a script of your choosing.

## 🛠️ Setup Walkthrough

Setting up SyncBack-2026 is a short journey with clear signposts. The following walkthrough avoids command-line rituals entirely — this is a graphical companion designed for humans.

1. **Obtain the package.** Use the placeholder marker above to locate the distribution bundle.
2. **Launch the installer.** A wizard greets you with a welcome screen and a short summary of what will be placed on disk.
3. **Choose an installation directory.** The default is sensible; advanced users may redirect to another volume.
4. **Select optional components.** Desktop shortcut, file-association hooks, and shell-context menu integration are each toggleable.
5. **Confirm and proceed.** The installer copies files, registers the application, and offers to launch immediately.
6. **First-run assistant.** On the first launch, a lightweight assistant asks where your important folders live and proposes an initial profile.
7. **Review the proposed profile.** Accept, modify, or discard. Nothing is committed until you approve.
8. **Run a dry-run pass.** Observe what the profile intends to do before any write operation.
9. **Execute the real pass.** Watch progress ribbons as files travel to their destination.
10. **Schedule future runs.** Choose a cadence — hourly, daily, weekly, or event-driven.

If any step fails, a human-readable message explains what happened and where to look. No cryptic exit codes are left hanging in a terminal window.

## 🗓️ Backup Profiles & Scheduling

A profile is a reusable recipe: source, destination, direction, filters, compression settings, and notifications. Profiles can be cloned, renamed, tagged, and grouped into folders for organizational clarity.

Scheduling options include:

- **Clock-based** — run at a specific time each day, week, or month.
- **Interval-based** — run every N minutes or hours while the machine is active.
- **Event-based** — trigger on logon, logoff, idle transition, or removable-media insertion.
- **Manual** — no automation; run on demand.
- **Chained** — start a second profile after the first completes successfully.

Each scheduled run records a summary: files considered, files transferred, bytes moved, duration, and any conflicts deferred to the user.

## ☁️ Cloud & Local Destination Handling

SyncBack-2026 writes to any destination Windows can address — internal drives, external USB volumes, network shares, and mounted cloud folders. The engine treats them uniformly, applying the same verification pipeline regardless of where the bytes land.

Notable destination behaviors:

- **Network resilience** — automatic retry with backoff when a share blips.
- **Bandwidth awareness** — optional throttle so backups do not starve streaming or video calls.
- **Removable media detection** — a profile can wait patiently until its target drive appears.
- **Path remapping** — restore to a different location than the original without rewriting the profile.

The philosophy is simple: the destination should be an implementation detail, not a complication for the user.

## 🔐 Security & Integrity Model

Trust is earned through verification. SyncBack-2026 applies checksums at multiple points in the pipeline so that corruption, truncation, or interception cannot slip through silently.

Security posture highlights:

- Checksums computed on read and re-computed on write.
- Integrity reports available for any historical run.
- No telemetry sent to external servers by default.
- Credentials for network shares stored using the operating system's protected credential store.
- Optional encryption of backup archives for at-rest protection.

Nothing about the design assumes a hostile environment, but nothing about it trusts blindly either. The middle path — cautious, verifying, transparent — is the one chosen.

## ❓ Frequently Asked Questions

**Does SyncBack-2026 only work on Windows 11?**
No. Windows 10 (64-bit) is fully supported. Windows 11 receives first-class attention in the 2026 release because it is the current mainstream platform.

**Can I run multiple profiles at once?**
Yes, with a queue system that prevents destination collisions. Profiles that target the same destination are serialized automatically.

**What happens if a file changes on both sides?**
The conflict resolver presents options: keep source, keep destination, keep both with a renamed copy, or defer the decision for later.

**Is there a way to test a profile without touching data?**
Yes. Dry-run mode produces a full report of intended actions without writing anything.

**Can profiles be shared with colleagues?**
Absolutely. Profiles export to a portable text format that can be committed, emailed, or stored in a repository.

**How are logs stored?**
Logs live in a rotating directory under the application data folder, with retention settings you control. Older entries age out gracefully.

**Does the tool require an always-on internet connection?**
No. SyncBack-2026 is a local-first application. Cloud destinations simply appear as mounted folders when available.
